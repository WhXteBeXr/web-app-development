# Разработка веб-приложений

Python и Django. Выполняются все уровни варианта 3 и общие задания. В первой методичке нет деления на варианты и уровни.

## Подготовка окружения

Команды выполнять из корня репозитория на Linux:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python --version
python -m django --version
```

В PyCharm выберите `.venv/bin/python`. Для запуска достаточно `requirements.txt`, файл `requirements-dev.txt` дополнительно устанавливает Ruff.

Каждая работа получает самостоятельную версию Django-проекта. Это позволяет запускать и защищать ее независимо от следующих работ. Исходники lab2-lab5 будут добавлены при выполнении соответствующей работы.

В корне находятся общие зависимости и настройки Ruff. В папках работ размещаются `report.md`, `defense.md` и `media/`.

`Project/` - первоначальная пользовательская заготовка, сохраненная с ее локальными изменениями. Новая лабораторная запускается из `lab1/`. Пустой исходный `main.py` для запуска Django не нужен.

## Запуск лабораторной 1

После активации окружения, из корня репозитория:

```bash
python lab1/manage.py migrate
python lab1/manage.py check
python lab1/manage.py runserver 127.0.0.1:8000
```

Откройте `http://127.0.0.1:8000/news/` и `http://127.0.0.1:8000/news/test/`. Остановка сервера: Ctrl+C. Корневой адрес `/` не зарегистрирован и возвращает 404, как в итоговой схеме методички.

Проверка оформления новой работы:

```bash
ruff check lab1
ruff format --check lab1
```

Сценарии и результаты приведены в [отчете](lab1/report.md), объяснение реализации в [памятке](lab1/defense.md).
