# Разработка веб-приложений

Один Django-проект на Python 3.14, который последовательно развивается в ходе пяти лабораторных. Выполняются все уровни варианта 3 и общие задания методичек. В первой работе варианты отсутствуют, во второй выполняется вариант 3 «Комментарии» без деления на уровни.

## Структура

```text
Project/
    manage.py
    config/             # настройки сайта
    news/               # приложение и миграции
    db.sqlite3          # локальная рабочая база
    uploads/            # изображения сайта
lab1/                   # отчет, памятка и результаты первой работы
lab2/                   # отчет, памятка, demo.py и результаты второй работы
lab3/                   # шаблоны, админка, отчет и памятка
lab4/                   # связи моделей, библиотека и категории
lab5/                   # Bootstrap, теги, фильтры и материалы работы
requirements.txt
requirements-dev.txt
pyproject.toml
```

Весь код сайта находится в `Project/`. В папках лабораторных хранятся документация, результаты и необходимые демонстрационные сценарии. Текущий проект содержит выполненные работы 1-5.

Новые работы выполняются в этом же проекте. При добавлении моделей, шаблонов и других возможностей проверяется и ранее реализованная функциональность. Отчеты описывают задачи соответствующих лабораторных, исходники по ссылкам показывают текущее общее решение.

## Первичная настройка

Все команды выполнять из корня репозитория на Linux:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python Project/manage.py migrate
python Project/manage.py check
```

Если окружение уже настроено, создавать его повторно не нужно. Для запуска достаточно `requirements.txt`, файл `requirements-dev.txt` дополнительно устанавливает Ruff.

## Запуск сайта

```bash
source .venv/bin/activate
python Project/manage.py runserver 127.0.0.1:8002
```

Открыть `http://127.0.0.1:8002/news/` или `http://127.0.0.1:8002/news/test/`. Корневой адрес `/` возвращает 404 по схеме первой работы. Остановка сервера: Ctrl+C. Если порт занят, выбрать свободный порт или остановить предыдущий свой сервер.

## Демонстрация работы 2

```bash
python Project/manage.py shell < lab2/demo.py
```

Сценарий проверяет CRUD, фильтрацию, рейтинг и ошибки. Временные строки откатываются, затем сохраняются три учебных комментария и новость с изображением. Повторный запуск исходных примеров не создает дубли. Пользовательские данные не очищаются.

## Шаблоны и админка, работа 3

`/news/` теперь отображает список новостей из базы, а не фиксированное приветствие. Страница `/news/test/` сохранена. Для добавления учебных новостей и входа в админку:

```bash
python Project/manage.py shell < lab3/demo.py
python Project/manage.py createsuperuser
```

Если администратор уже создан, используйте его учетную запись. Затем запустите сайт и откройте `/admin/`. В админке доступны новости и комментарии. У новостей настроены колонки, ссылки редактирования и поиск по заголовку и содержанию. Фотография необязательна.

Лента показывает все учебные записи со статусом публикации. Подробный сценарий: [лабораторная 3](lab3/README.md).

## Связи моделей, работа 4

После миграций добавьте учебные данные:

```bash
python Project/manage.py shell < lab4/demo.py
```

В админке появились авторы, книги и категории. У книг настроены автор, фильтры, поиск и редактирование года прямо в списке. У новостей отображается категория, доступны фильтры и изменение публикации в списке.

Удаление автора через ORM или админку удаляет его книги. Категория с новостями защищена от удаления. Подробности: [лабораторная 4](lab4/README.md).

## Оформление, работа 5

```bash
python Project/manage.py shell < lab5/demo.py
```

Лента `/news/` оформлена карточками Bootstrap. Текст сокращается до 50 слов, «Подробнее» открывает полную новость по адресу `/news/<id>/`. Даты, категории, статусы и фотографии сохранены, без фото используется локальная заглушка. Навигация адаптируется к узкому экрану.

Bootstrap CSS и JS загружаются с CDN, локальные стили и изображение находятся в `Project/news/static/news/`. Дополнительная сборка фронтенда не требуется. Подробности: [лабораторная 5](lab5/README.md).

## Изменение моделей и проверка

```bash
python Project/manage.py makemigrations
python Project/manage.py migrate
python Project/manage.py check
ruff check Project lab2/demo.py lab3/demo.py lab4/demo.py lab5/demo.py
ruff format --check Project lab2/demo.py lab3/demo.py lab4/demo.py lab5/demo.py
```

Миграции остаются частью Django-проекта: они применяют изменения моделей к рабочей базе. Каждая следующая лабораторная дополняет общий сайт.

## PyCharm и данные

Открывать корень репозитория. Интерпретатор: `.venv/bin/python`. Sources Root: каталог `Project/`, содержащий `manage.py`, `config` и `news`.

Локальная конфигурация «Django - общий проект» запускает `Project/manage.py` с аргументами `runserver 127.0.0.1:8002`. Рабочая папка - корень репозитория. Модуль настроек Django: `config.settings`.

База находится в `Project/db.sqlite3`, файлы изображений в `Project/uploads/`. Они исключены из Git. Подключение Database в PyCharm указывает на эту же базу. Каталог `labN/media/` содержит материалы отчета и не используется как хранилище загрузок сайта.

Ранее сохраненные журналы проверок содержат команды, которые выполнялись на момент проверки. Для актуального запуска используй команды из этого файла.
