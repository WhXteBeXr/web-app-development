## Цель работы

Настроить виртуальное окружение Python, создать Django-проект, разработать контроллеры приложения и организовать маршруты.

## Постановка задачи

Методичка лабораторной 1 не содержит индивидуальных вариантов, уровней сложности и контрольных вопросов. Выполняется вся описанная практическая часть:

1. Подготовить и активировать виртуальное окружение.
2. Установить Django и создать проект.
3. Создать приложение `news` и зарегистрировать его в настройках.
4. Реализовать контроллер приветствия и контроллер тестовой страницы.
5. Создать корневой маршрутизатор и отдельный маршрутизатор приложения.
6. Подключить приложение через `include()` и открыть `/news/` и `/news/test/`.
7. Запустить сервер и проверить поведение маршрутов.

## Теоретическая часть

Виртуальное окружение изолирует зависимости проекта от системных библиотек Python. Команда `python -m pip` использует установщик выбранного интерпретатора. Зависимости зафиксированы в `requirements.txt`.

Django-проект содержит конфигурацию сайта, а приложение реализует отдельную функциональную область. В данной работе проект называется `config`, приложение называется `news`.

При обработке запроса Django сначала использует `ROOT_URLCONF`. Функция `path()` сопоставляет путь и обработчик. Функция `include()` передает оставшуюся часть пути другому маршрутизатору. Например, для `/news/test/` корневой маршрутизатор обрабатывает `news/`, а `news.urls` сопоставляет `test/` с контроллером `test`.

Контроллер принимает `HttpRequest` и возвращает `HttpResponse`. Ответ содержит статус, заголовки и тело. По умолчанию `HttpResponse` использует `text/html`, поэтому строка с `<h1>` отображается как HTML-заголовок. Для неизвестного адреса Django возвращает 404.

## Исходные файлы и реализация

[manage.py](../Project/manage.py) запускает команды Django. [config/settings.py](../Project/config/settings.py) содержит настройки, регистрацию `news.apps.NewsConfig`, конфигурацию SQLite и русскую локализацию. [config/urls.py](../Project/config/urls.py) подключает административную панель и маршруты приложения.

[news/apps.py](../Project/news/apps.py) описывает конфигурацию приложения. [news/urls.py](../Project/news/urls.py) задает два именованных маршрута. [news/views.py](../Project/news/views.py) содержит контроллеры `index` и `test`. Модули `models.py` и `admin.py` подготовлены для дальнейшего развития сайта, пользовательских моделей в этой работе нет. `config/asgi.py` и `config/wsgi.py` предоставляют стандартные точки входа для серверов Django.

Контроллеры возвращают фиксированный текст без доступа к базе данных. Декоратор `require_safe` разрешает GET и HEAD. При POST сначала выполняется проверка CSRF. Без токена возвращается 403, с корректным токеном запрос доходит до декоратора и получает 405 с заголовком `Allow: GET, HEAD`.

## Практическая часть

Создано окружение Python 3.14.10 с Django 6.1.1. Версии Django и его зависимостей закреплены в [requirements.txt](../requirements.txt). Для проверки оформления используется Ruff 0.16.8.

Общий Django-проект размещен в `Project/`. Эта работа описывает этап создания окружения, контроллеров и маршрутов. Приложение зарегистрировано в `INSTALLED_APPS`. Корневой маршрут `news/` подключает `news.urls`, где пустой путь вызывает `index`, а `test/` вызывает `test`.

Применены 18 стандартных миграций административной панели, авторизации, типов содержимого и сессий. Дополнительные миграции не нужны, поскольку собственные модели не создавались.

## Маршруты и ответы

Это HTML-страницы учебного приложения, параметры и JSON-тела им не требуются.

| Метод   | Путь                                   | Назначение и ответ                                                 |
|---------|----------------------------------------|--------------------------------------------------------------------|

## Запуск

Команды выполняются из корня репозитория на Linux:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python Project/manage.py migrate
python Project/manage.py check
python Project/manage.py runserver 127.0.0.1:8000
```

После запуска открыть `http://127.0.0.1:8000/news/` и `http://127.0.0.1:8000/news/test/`. Остановить сервер сочетанием Ctrl+C. Корень `/` не зарегистрирован и возвращает 404. Для входа в административную панель при необходимости создать учетную запись командой `python Project/manage.py createsuperuser`. В выполненные сценарии входит открытие формы входа без создания учетной записи.
